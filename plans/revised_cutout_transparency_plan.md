# 闭合区域抠图透明导出问题修正版开发计划

## 1. 当前问题说明

当前导出的结果存在以下问题：

1. 闭合区域内的背景没有被透明化。
2. 导出的 SVG 中仍然保留白底或原图背景。
3. 某些区域内还残留了其他元素。
4. 当前效果更接近“区域裁剪”，而不是“元素抠图”。

这说明当前核心逻辑还没有达到目标。软件不能只把闭合区域对应的外接矩形裁出来，而是必须在闭合区域约束内进一步提取前景，并正确写入 alpha 透明通道。

---

## 2. 修正后的产品定位

原定位：

> 用户画闭合区域，软件把区域裁剪出来并导出 SVG。

修正后定位：

> 用户画闭合区域，软件在闭合区域内提取目标元素，去除白底或浅色背景，生成透明 PNG，并以内嵌 PNG 的方式导出为独立 SVG。

第一版仍然不做真正矢量化 SVG，也不使用 AI 智能抠图，而是优先实现轻量、稳定、可运行的透明抠图闭环。

---

## 3. 当前阶段优先级调整

当前不建议继续优先增加新功能，也不建议优先处理安装包问题。

新的优先级如下：

### P0：修复透明导出链路

必须确保最终导出的 PNG 是真正带 alpha 通道的透明 PNG。

验收标准：

- 导出的 PNG 使用棋盘格背景查看时，背景应为透明。
- SVG 中嵌入的 PNG 背景也应为透明。
- 程序中不能在保存前将图像转为 RGB。
- 程序中不能把透明图重新贴到白色背景上。

### P1：增加闭合区域内前景提取

必须解决“区域内白底仍然保留”的问题。

验收标准：

- 白底或浅色背景能够被去除。
- 闭合区域外全部透明。
- 闭合区域内只尽量保留目标元素。

### P2：增加残留清理机制

用于处理区域内多余小元素、噪点、碎片残留。

验收标准：

- 可以去除小面积孤立噪点。
- 可以选择保留最大连通域。
- 第一张图中类似多余残留元素应明显减少。

### P3：继续完善软件功能

在抠图核心逻辑达标后，再继续开发：

- 多图片导入
- 多区域管理
- 区域命名
- 批量导出
- 导出失败列表
- 文件命名规则
- 打包发布

---

## 4. 修正后的核心处理流程

每个闭合区域的处理流程应修改为：

1. 用户绘制闭合区域。
2. 根据闭合区域生成用户区域 mask。
3. 计算闭合区域外接矩形 ROI。
4. 裁剪原图 ROI。
5. 在 ROI 内进行前景提取。
6. 将前景 mask 与用户区域 mask 相交。
7. 对最终 mask 做轻微羽化。
8. 使用最终 mask 写入 alpha 通道。
9. 输出透明 PNG。
10. 将透明 PNG 内嵌到 SVG。

最终 mask 逻辑为：

```text
final_mask = user_region_mask AND foreground_mask
```

含义：

- 用户区域外一定透明。
- 用户区域内不再全部保留，而是只保留识别出的前景元素。

---

## 5. 前景提取策略

第一版建议优先支持白底或浅色背景去除，因为当前测试图像大概率属于白底元素图。

### 5.1 白底阈值去除

适用场景：

- 背景接近白色。
- 图案颜色明显不同于背景。
- 图片为插画、图标、示意图、医学或工程小图。

基本规则：

```text
如果 R、G、B 都大于某个阈值，则认为该像素是背景。
```

建议默认阈值：

```text
R > 240, G > 240, B > 240
```

可调参数：

| 参数 | 默认值 | 说明 |
|---|---:|---|
| 白色阈值 | 240 | 越小，去背景越强 |
| 近白容差 | 15 | 用于处理轻微灰白背景 |
| 最小前景面积 | 20 px² | 小于该面积视为噪点 |

优点：

- 实现简单。
- 不依赖 AI。
- 运行速度快。

缺点：

- 目标元素中接近白色的部分可能被误删。
- 复杂背景效果一般。

---

### 5.2 边界 Flood Fill 去背景

为了避免目标元素内部浅色部分被误删，建议增加边界连通背景识别。

处理思路：

1. 在 ROI 内，从四周边界开始寻找近白像素。
2. 将与边界连通的近白区域判定为背景。
3. 不与边界连通的浅色区域可以保留。
4. 背景区域设为透明。

适用场景：

- 背景是连通白底。
- 目标元素内部也可能有浅色细节。

优点：

- 比单纯阈值更稳。
- 不容易误删元素内部浅色区域。

第一版建议：

> 优先实现边界 Flood Fill 去背景，而不是只做全图白色阈值。

---

### 5.3 保留最大连通域

用于解决区域内仍然残留其他元素的问题。

处理思路：

1. 得到初步前景 mask。
2. 做连通域分析。
3. 默认保留最大连通域。
4. 去除其他小连通区域。

适用场景：

- 闭合区域内混入多个小元素。
- 背景去除后仍有噪点。
- 用户只希望导出一个主体元素。

注意：

如果一个目标本身由多个分离部分组成，例如文字、多个零件、多个独立线条，单纯保留最大连通域可能会误删有效内容。

因此建议提供开关：

```text
[ ] 只保留最大连通域
```

默认建议：

- 对普通插画元素：开启。
- 对复杂多部件图形：关闭。

## 6. Alpha 通道写入要求

透明导出必须满足以下规则：

1. 原图读取后统一转换为 RGBA。
2. ROI 图像必须保留 RGB 颜色信息。
3. 最终 mask 必须写入 alpha 通道。
4. 保存 PNG 时必须保存为 RGBA。
5. 任何导出阶段都不能转为 RGB。
6. SVG 中嵌入的必须是带 alpha 的 PNG。

需要重点排查并避免以下代码或逻辑：

```python
image.convert("RGB")
Image.new("RGB", size, "white")
transparent_image.paste(image_without_mask)
```

推荐逻辑：

```python
rgba = roi.convert("RGBA")
rgba.putalpha(final_mask)
rgba.save(output_png_path)
```

如果先生成内存 PNG 再写入 SVG，也必须确保内存中的 PNG 是 RGBA 格式。

---

## 7. SVG 导出修正要求

SVG 仍然采用内嵌 PNG 方式，不做真正矢量化。

导出结构：

```xml
<svg width="区域宽度" height="区域高度" viewBox="0 0 区域宽度 区域高度" xmlns="http://www.w3.org/2000/svg">
  <image href="data:image/png;base64,..." width="区域宽度" height="区域高度"/>
</svg>
```

要求：

- 内嵌 PNG 必须是透明 PNG。
- SVG 不应额外设置白色背景矩形。
- SVG 根节点不应添加白色 `background`。
- 不应生成 `<rect fill="white">` 作为底图。

## 8. 修正后的最小可用版本目标

当前阶段的 MVP 应该收缩为：

1. 导入单张图片。
2. 绘制一个闭合区域。
3. 在闭合区域内去除白底。
4. 输出透明 PNG。
5. 输出内嵌透明 PNG 的 SVG。
6. 验证导出文件透明背景正确。

暂时不要求：

- 多图片批量导入。
- 多区域导出。
- 区域列表管理。
- 复杂 GUI 美化。
- 打包为 exe。

## 9. 推荐开发步骤

### 阶段 1：单独验证透明 PNG 输出

目标：不经过 SVG，先确保 PNG 透明。

实现：

- 打开图片。
- 手动或程序指定一个测试区域。
- 生成 user_region_mask。
- 执行白底去除。
- 写入 alpha。
- 保存透明 PNG。

验收：

- PNG 背景透明。
- 图片查看器或网页棋盘格背景下确认透明。

---

### 阶段 2：加入 SVG 内嵌导出

目标：验证 SVG 不破坏透明度。

实现：

- 将阶段 1 得到的透明 PNG 转成 base64。
- 写入 SVG `<image>`。
- 打开 SVG 检查透明效果。

验收：

- SVG 打开后背景透明。
- SVG 内没有白色底图。

---

### 阶段 3：接入闭合区域绘制

目标：把手动画的闭合区域作为 user_region_mask。

实现：

- 矩形区域。
- 椭圆区域。
- 自由闭合曲线区域。

验收：

- 区域外透明。
- 区域内白底去除。
- 导出结果只保留目标元素。

---

### 阶段 4：增加残留清理

目标：减少区域内多余小元素。

实现：

- 连通域分析。
- 去除小面积噪点。
- 可选保留最大连通域。

验收：

- 小碎片减少。
- 主体元素保留。

---

### 阶段 5：恢复批量功能开发

在抠图效果达标后，再继续实现：

- 多图片导入。
- 每张图片多个区域。
- 区域命名。
- 每个区域一个 SVG。
- 批量导出。
- 导出失败列表。

## 12. 当前最重要的验收标准

在继续开发其他功能之前，必须先满足以下标准：

1. 单个区域导出的 PNG 是透明背景。
2. 单个区域导出的 SVG 是透明背景。
3. 闭合区域外完全透明。
4. 闭合区域内白底或浅色背景基本去除。
5. 导出时不残留明显白色矩形背景。
6. 代码中不存在导致 alpha 丢失的 RGB 转换。

## 14. 最终结论

当前问题的本质不是界面问题，也不是安装包问题，而是核心抠图逻辑还没有达到目标。

因此，下一步应优先完成：

```text
闭合区域约束 + 白底去除 + alpha 透明导出 + SVG 保持透明
```

只有当这个核心闭环稳定后，再继续开发批量管理、区域编辑、导出体验和打包发布功能。
