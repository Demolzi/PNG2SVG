# 非 AI 抠图质量提升方案计划书

## 1. 方案目标

本计划用于提升当前“闭合区域抠图并导出 SVG”软件的抠图质量，但不使用 AI 模型、不引入 rembg、U²-Net、SAM 等深度学习方案。

目标是基于用户绘制的闭合区域，在区域内部进一步识别前景元素，去除白底、浅色背景、边缘白边和小噪点，最终输出透明背景 PNG，并以内嵌 PNG 的形式写入 SVG。

最终效果目标：

1. 区域外完全透明。
2. 区域内的白底或浅色连通背景尽量透明。
3. 小噪点、残留碎片可被过滤。
4. 目标边缘尽量自然，减少白边、锯齿和脏边。
5. 所有算法保持本地、轻量、可打包。

---

## 2. 总体算法路线

建议将非 AI 抠图分为三类模式：

| 模式 | 适用场景 | 是否第一版推荐 |
|---|---|---|
| 区域裁剪模式 | 用户只想保留闭合区域内全部内容 | 保留 |
| 白底去除模式 | 白底、浅色背景、产品图、插画、截图 | 优先实现 |
| GrabCut 分割模式 | 背景稍复杂、目标边界较明显 | 第二阶段实现 |

推荐软件界面中提供“抠图模式”选项：

```text
抠图模式：
[仅区域裁剪]
[白底/浅色背景去除]
[GrabCut 智能分割（非 AI）]
```

其中“白底/浅色背景去除”作为默认模式，“仅区域裁剪”作为兜底模式，“GrabCut”作为增强模式。

---

## 3. 模式一：仅区域裁剪

### 3.1 功能定位

该模式不识别区域内部背景，只根据用户绘制的闭合区域生成透明蒙版。

处理结果是：

- 闭合区域外透明；
- 闭合区域内保留原图像素；
- 不主动去除区域内部白底、背景或杂物。

### 3.2 适用场景

适合以下情况：

1. 用户希望完整保留闭合区域内所有内容。
2. 图片本身已经是透明背景。
3. 用户绘制区域已经非常贴合目标轮廓。
4. 白底去除或 GrabCut 误删目标时，用作安全模式。

### 3.3 处理流程

```text
原图
→ 用户闭合区域 polygon
→ 生成区域 mask
→ 计算区域外接矩形 ROI
→ 裁剪 ROI
→ 将区域 mask 写入 alpha 通道
→ 输出透明 PNG
→ 内嵌到 SVG
```

### 3.4 验收标准

1. 区域外必须透明。
2. 区域内图像必须完整保留。
3. 输出 PNG 必须为 RGBA 格式。
4. SVG 打开后背景透明。

---

## 4. 模式二：白底 / 浅色背景去除

### 4.1 功能定位

该模式用于解决当前软件中“闭合区域内部仍然保留白底”的问题。

它不是 AI 抠图，而是基于颜色阈值、边界连通背景识别、连通域过滤和边缘处理完成前景提取。

### 4.2 适用场景

适合：

1. 白底产品图。
2. 浅色背景上的元素。
3. 截图、图标、插画。
4. 背景颜色较统一的图片。
5. 用户闭合区域内包含目标元素和少量白底背景的情况。

不适合：

1. 背景颜色复杂。
2. 目标本身大面积接近白色。
3. 阴影、半透明、毛发等复杂边缘。
4. 前景和背景颜色非常接近。

### 4.3 推荐处理流程

```text
原图
→ 用户闭合区域 polygon
→ 生成 user_region_mask
→ 裁剪 ROI
→ 在 ROI 内识别近白背景候选像素
→ 从 ROI 边界执行 flood fill
→ 得到与边界连通的背景 mask
→ foreground_mask = user_region_mask - background_mask
→ 连通域过滤
→ mask 平滑与边缘羽化
→ 去白边处理
→ 写入 alpha 通道
→ 输出透明 PNG
→ 内嵌到 SVG
```

### 4.4 关键算法模块

#### 4.4.1 近白背景判断

当前可以先使用 RGB 判断：

```text
R >= white_threshold
G >= white_threshold
B >= white_threshold
```

默认参数建议：

```text
white_threshold = 240
near_white_tolerance = 15
```

增强版建议加入 HSV 或 Lab 判断：

```text
HSV：低饱和度 + 高亮度 → 背景候选
Lab：高 L 值 + 低色差 → 背景候选
```

建议判断逻辑：

```text
如果像素满足以下任意条件，则视为近白背景候选：
1. RGB 三通道都高于阈值；
2. HSV 中 V 高、S 低；
3. 与边界背景采样色的颜色距离小于阈值。
```

#### 4.4.2 边界 Flood Fill

只从 ROI 四周边界开始搜索背景，避免误删目标内部的白色区域。

核心逻辑：

```text
从 ROI 上下左右边界入队
→ 只扩展近白背景候选像素
→ 只允许在 user_region_mask 内扩展
→ 得到与边界连通的背景区域
```

这样可以避免把目标内部封闭的白色区域误删。

#### 4.4.3 连通域过滤

前景 mask 生成后，可能会有小噪点或残留碎片。

建议提供两个选项：

```text
去除小噪点：开启 / 关闭
最小噪点面积：默认 20 px²
只保留最大连通域：开启 / 关闭
```

处理规则：

1. 如果开启“去除小噪点”，删除面积小于阈值的前景连通域。
2. 如果开启“只保留最大连通域”，只保留面积最大的前景区域。
3. 如果所有连通域都小于阈值，至少保留最大连通域，避免结果为空。

#### 4.4.4 形态学处理

用于修复 mask 毛刺和小孔洞。

建议加入：

```text
开运算：去除小毛刺
闭运算：填补小孔洞
轻微膨胀：修复边缘缺口
轻微腐蚀：去除白边外围
```

第一版可先提供固定处理：

```text
开运算 1 次
闭运算 1 次
```

后续可以在界面中开放参数。

#### 4.4.5 边缘羽化

当前羽化半径建议：

```text
默认：1.0 到 1.5 px
可调范围：0 到 5 px
```

注意：羽化过大可能导致目标边缘变糊，特别是小图标、小零件和细线图。

#### 4.4.6 去白边处理

白底图在透明化后，经常会出现目标边缘残留白色像素。

建议增加“去白边强度”：

```text
去白边强度：0 / 1 / 2 / 3
默认：1
```

处理思路：

1. 找到 alpha 边缘区域。
2. 对边缘处接近白色的像素进行颜色修正。
3. 将边缘 RGB 向附近内部前景色靠近。
4. 保持 alpha 不变或轻微调整。

简化版可以先做：

```text
如果边缘像素 alpha 较低，且 RGB 接近白色，降低其 RGB 亮度或用邻近非白前景像素均值替换。
```

### 4.5 推荐参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| white_threshold | 240 | 白底阈值 |
| near_white_tolerance | 15 | 近白容差 |
| feather_radius | 1.5 | 边缘羽化半径 |
| min_component_area | 20 | 最小噪点面积 |
| remove_small_components | true | 是否去除小噪点 |
| keep_largest_component | false | 是否只保留最大连通域 |
| morph_open_iterations | 1 | 开运算次数 |
| morph_close_iterations | 1 | 闭运算次数 |
| defringe_strength | 1 | 去白边强度 |

### 4.6 验收标准

1. 白底区域应变透明。
2. 与 ROI 边界连通的浅色背景应被去除。
3. 目标主体应保留。
4. 小噪点应明显减少。
5. 边缘白边应比当前版本更少。
6. 输出 PNG 必须保留 alpha 通道。

## 5. 模式三：GrabCut 分割模式

### 5.1 功能定位

GrabCut 是 OpenCV 中的传统图像分割算法，不属于 AI 深度学习模型。

它适合在用户已经给出闭合区域、矩形或大致范围的情况下，进一步自动分离前景和背景。

### 5.2 适用场景

适合：

1. 背景不是纯白，但目标和背景有一定颜色差异。
2. 目标边界较清晰。
3. 用户画出的区域大致包住目标。
4. 白底去除模式效果不佳的图片。

不适合：

1. 前景和背景颜色非常接近。
2. 目标边界模糊。
3. 毛发、透明物体、复杂阴影。
4. 用户区域画得过大，包含太多相似背景。

### 5.3 推荐处理流程

```text
原图
→ 用户闭合区域 polygon
→ 计算 ROI
→ 生成 GrabCut 初始 mask
→ 区域外标记为确定背景
→ 区域内标记为可能前景
→ 可选：区域中心或最大连通区域标记为确定前景
→ OpenCV GrabCut 迭代
→ 得到前景 mask
→ 与 user_region_mask 相交
→ 连通域过滤
→ 边缘平滑
→ 去白边处理
→ 输出透明 PNG
→ 内嵌到 SVG
```

### 5.4 GrabCut 初始化策略

建议采用 mask 初始化，而不是只用矩形初始化。

初始 mask 设置：

```text
用户区域外：GC_BGD，确定背景
用户区域内：GC_PR_FGD，可能前景
区域中心或经过颜色判断的深色区域：GC_FGD，可选确定前景
```

如果用户画的是矩形区域，也可以直接用矩形初始化作为简化版本。

### 5.5 推荐参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| grabcut_iterations | 5 | GrabCut 迭代次数 |
| use_polygon_mask | true | 使用闭合区域作为初始 mask |
| post_remove_small_components | true | 后处理去噪 |
| post_keep_largest_component | false | 后处理保留最大连通域 |
| post_feather_radius | 1.0 | 后处理羽化 |

### 5.6 失败兜底策略

GrabCut 可能出现结果为空、结果过大或误删目标的情况。

建议加入兜底：

1. 如果前景面积小于用户区域面积的 1%，认为分割失败。
2. 如果前景面积大于用户区域面积的 95%，认为分割没有起效。
3. 分割失败时自动回退到“白底去除模式”或“仅区域裁剪模式”。
4. 在导出失败列表中记录具体原因。

### 5.7 验收标准

1. 复杂背景下应比白底去除模式更有机会分离目标。
2. 结果不能超出用户闭合区域。
3. 分割失败时不能输出空图。
4. 至少保留一个兜底模式。

---

## 6. 边缘优化专项

无论使用哪种模式，最终边缘质量都很重要。

### 6.1 Mask 平滑

建议处理顺序：

```text
粗 mask
→ 去除小噪点
→ 填补小孔洞
→ 轻微腐蚀或膨胀
→ 高斯羽化
→ 与用户区域 mask 相交
```

### 6.2 去白边

白底图片透明化后，目标边缘可能残留白色像素。建议在所有模式后统一执行去白边。

处理对象：

```text
alpha 在 1 到 254 之间的半透明边缘像素
或 alpha 较低但 RGB 接近白色的像素
```

处理策略：

```text
边缘像素颜色 = 附近高 alpha 前景像素颜色的加权平均
```

第一版可以先实现简化策略，后续再优化为邻域采样。

### 6.3 锯齿处理

建议：

1. mask 生成时使用高分辨率或亚像素绘制。
2. 输出前对 alpha 边缘做 0.5 到 1.5 px 羽化。
3. 不要对小图使用过大的羽化半径。

## 8. 推荐代码结构调整

建议在 `core/mask.py` 中拆分算法函数，避免所有逻辑堆在一个函数里。

```text
core/
  mask.py
  cutout_modes.py
  background_remove.py
  grabcut.py
  edge_refine.py
  components.py
```

建议模块职责：

| 文件 | 职责 |
|---|---|
| mask.py | 总入口，根据模式调用不同算法 |
| background_remove.py | 白底/浅色背景去除 |
| grabcut.py | GrabCut 分割 |
| edge_refine.py | 羽化、去白边、mask 平滑 |
| components.py | 连通域过滤 |
| cutout_modes.py | 抠图模式枚举和参数结构 |

## 9. 实施阶段计划

### 阶段 1：稳定透明输出链路

目标：确保当前导出结果一定有透明 alpha。

任务：

1. 检查所有输出是否为 RGBA。
2. 禁止导出前转换为 RGB。
3. 单独导出 PNG 做透明度验证。
4. SVG 内嵌 PNG 前确认 PNG alpha 正常。

验收：

1. PNG 在棋盘格背景中查看时透明正常。
2. SVG 打开后背景透明。
3. 区域外不再出现白底。

---

### 阶段 2：增强白底去除

目标：解决白底、浅色背景残留。

任务：

1. 增强近白判断逻辑。
2. 保留边界 flood fill。
3. 增加 HSV 或 Lab 判断。
4. 增加小噪点过滤。
5. 增加最大连通域保留选项。
6. 增加 mask 开闭运算。

验收：

1. 白底图片导出后背景基本透明。
2. 小残留明显减少。
3. 目标主体不被明显误删。

---

### 阶段 3：边缘质量优化

目标：减少白边、锯齿和脏边。

任务：

1. 增加去白边参数。
2. 优化羽化半径。
3. 增加 mask 平滑流程。
4. 对小图限制最大羽化半径。

验收：

1. 目标边缘白边减少。
2. 轮廓不明显发糊。
3. 小图边缘不被过度羽化。

---

### 阶段 4：加入 GrabCut 模式

目标：提升非纯白背景场景的抠图能力。

任务：

1. 安装并接入 OpenCV。
2. 实现 GrabCut mask 初始化。
3. 将用户区域外设置为确定背景。
4. 用户区域内设置为可能前景。
5. GrabCut 输出后与用户区域 mask 相交。
6. 增加失败检测和回退机制。

验收：

1. GrabCut 模式可正常导出透明 PNG。
2. 分割结果不超出用户区域。
3. 失败时自动回退，不输出空图。

---

### 阶段 5：预览与参数调试

目标：让用户能在导出前调整参数。

任务：

1. 增加当前区域预览。
2. 增加参数修改后重新预览。
3. 增加恢复默认参数按钮。
4. 可选：保存最近一次参数设置。

验收：

1. 用户可以对当前区域预览抠图效果。
2. 调整阈值、羽化、去白边后能看到变化。
3. 批量导出前可以确认质量。

---

## 10. 推荐优先级

建议按以下顺序实现：

```text
P0：确认 RGBA 透明输出链路
P1：增强白底/浅色背景去除
P2：连通域过滤与最大连通域保留
P3：mask 开闭运算与边缘羽化
P4：去白边处理
P5：GrabCut 模式
P6：抠图预览与参数保存
```

当前最应该优先做的是：

```text
白底去除增强 + 连通域过滤 + 边缘去白边
```

不建议当前阶段立刻把主要精力放在 GUI 美化、打包或 AI 模型接入上。

---

## 11. 主要风险与应对

### 风险 1：目标本身包含白色区域

白底去除可能误删目标中的白色部分。

应对：

1. 使用边界 flood fill，只去除与边界连通的白色区域。
2. 不直接删除所有白色像素。
3. 保留“仅区域裁剪”兜底模式。

### 风险 2：目标边缘有白边

透明化后残留白色边缘。

应对：

1. 增加去白边处理。
2. 使用边缘邻域前景色修正。
3. 羽化半径不要过大。

### 风险 3：GrabCut 结果不稳定

传统算法无法保证所有图片都成功。

应对：

1. 增加失败检测。
2. 增加自动回退。
3. 保留白底去除和区域裁剪模式。

### 风险 4：处理速度变慢

连通域、GrabCut 和边缘处理可能增加耗时。

应对：

1. 只对 ROI 处理，不对整张图处理。
2. 大图预览使用缩略图。
3. 批量导出时显示进度。
4. 可选关闭高级处理。

---

## 12. 最终推荐方案

第一阶段不要上 AI，建议采用以下组合：

```text
用户闭合区域约束
+ 边界 Flood Fill 白底去除
+ HSV/Lab 近白判断
+ 连通域过滤
+ 最大连通域选项
+ mask 开闭运算
+ 边缘羽化
+ 去白边处理
```

第二阶段再加入：

```text
OpenCV GrabCut 分割模式
```

最终软件中保留三种非 AI 抠图模式：

```text
1. 仅区域裁剪
2. 白底/浅色背景去除
3. GrabCut 分割
```

这样既能保证基础稳定，又能逐步提升复杂图片的抠图质量，并且不会引入大型 AI 模型、模型下载、推理速度和打包体积等问题。
